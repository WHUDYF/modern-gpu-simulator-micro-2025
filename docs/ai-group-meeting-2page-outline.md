# AI GPU 研究方向组会提纲

日期：2026-04-03

## 这次想讲清楚的核心问题

如果我们的目标是提升 GPU 在 AI 场景下的效率，那么后续研究不应该只围绕传统微基准展开，而应该由 AI workload 提出真实需求，再通过模拟、瓶颈定位和局部验证形成闭环。

一句话概括：

`AI workload 提出问题，模型级模拟发现问题，微基准解释问题，架构优化解决问题，最后再回到 AI workload 验证结果。`

## 为什么不能只看微基准

微基准的价值在于看局部机制，例如：

- cache 行为
- memory bandwidth / latency
- shared memory
- atomic
- 调度与并行度

但只看微基准会有两个问题：

- 只能证明局部机制变化了，不能证明真实 AI 模型更快了
- 容易出现“局部优化很好看，但系统收益不明显”的情况

因此，微基准更适合作为分析工具，而不是需求来源。

## 为什么必须引入 AI workload

AI workload 才能定义什么问题是真正值得优化的。

例如：

- 长上下文 LLM 推理更关心 memory efficiency
- attention-heavy workload 更容易暴露 cache / bandwidth 问题
- 推理更关心 latency
- 训练更关心 throughput 和能效

也就是说，AI workload 不应该只是最后展示结果的 benchmark，而应该是一开始就决定研究方向的输入。

## 建议采用的研究闭环

建议把后续研究主线固定成下面这条：

1. 定义目标 AI 场景
2. 选择代表性模型和输入规模
3. 做模型级模拟，观察端到端指标
4. 找到主导时间的 kernel
5. 用相关微基准验证瓶颈机理
6. 提出针对性的架构优化
7. 回到模型级 workload 做最终验收

这个闭环的好处是：

- 问题来源真实
- 瓶颈解释清楚
- 优化方向有针对性
- 最终结果可回到应用层验证

## 这里的分工关系

在这条路线里：

- AI workload 负责定义“什么值得优化”
- 模型级模拟负责定义“哪里最值得看”
- 微基准负责解释“为什么这里慢”
- 架构优化负责回答“要改什么”
- 模型级回验负责判断“改动是否真的有价值”

这几个部分不是替代关系，而是前后衔接的关系。

## 一个可操作的例子

例如，假设我们关心长上下文 LLM 推理：

1. 先用模型级模拟看 tokens/s、latency、memory traffic
2. 发现热点主要集中在 KV cache 访问相关 kernel
3. 再用 memory / cache 相关微基准看是不是带宽或 cache 行为受限
4. 如果确认是 memory hierarchy 的问题，再提出更贴合 KV cache 访问模式的优化
5. 最后回到 LLM 推理 workload，看端到端是否真的提升

这个例子说明，微基准不是起点，而是服务于模型级问题的分析工具。

## 我们近期可以怎么推进

如果只做第一轮闭环，建议先收敛，不要铺太大：

1. 只选一个代表性 AI workload
2. 只盯一类最主要的瓶颈
3. 只挑几个最相关的微基准
4. 只做一到两个明确的优化点
5. 一定回到模型级做验收

第一轮最重要的不是覆盖面，而是先证明这条方法能跑通。

## 组会上可以讨论的几个问题

- 第一条闭环应该选哪个 AI workload
- 我们更关注训练还是推理
- 第一轮更适合从 compute-bound 还是 memory-bound 问题切入
- 当前模拟器更适合承接哪类 workload
- 第一轮的成功标准应该怎么定义

## 近期里程碑建议

### 近期

- 确定一个代表性 AI workload
- 明确模型级指标
- 跑出第一版 baseline

### 中期

- 找出主要热点 kernel
- 建立热点和微基准之间的对应关系
- 形成第一版瓶颈归因

### 后期

- 提出并实现局部优化
- 回到模型级 workload 验证
- 判断该优化是否具有泛化性

## 风险

这条路线的主要风险包括：

- AI workload 太复杂，热点不容易收敛
- 模型级模拟成本高，迭代速度会慢
- 局部优化未必能稳定转化为端到端收益
- 不同 workload 的瓶颈可能差异很大

但这些风险并不否定路线本身，只说明需要分阶段推进。

## 组会结论版本

如果最后只留一页结论，可以讲这三点：

1. 后续研究需要从 AI workload 出发，而不是只从微基准出发。
2. 微基准仍然重要，但它的角色应当是解释模型级瓶颈，而不是替代模型级需求。
3. 最合理的研究路径是建立“模型提出问题、微基准解释问题、模型验证结果”的闭环。
