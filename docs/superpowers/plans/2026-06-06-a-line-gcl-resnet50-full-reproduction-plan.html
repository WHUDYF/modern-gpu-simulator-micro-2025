GCL ResNet-50 Full Reproduction Plan

从真实完整 ResNet-50 NVBit trace 开始，复现 GCL graph、RGCN embedding、silhouette-K / K-Means selector 和 representative anchors； 然后用 Gate7 量化分组正确性，最后再进入我们的 tuning vector 和 sampled-vs-full simulator evaluation 扩展。

Gate 0-6 构成 GCL-Sampler 核心复现路径。
Gate 7 量化 cluster correctness，不伪装成已证明正确。
Gate 8-9 属于我们的扩展：调参 proposal 与 simulator evaluation。
硬约束 formal path 必须来自真实完整 ResNet-50 NVBit trace。

完整 Phase 路线

实现顺序必须先复现 GCL，再验证 GCL，再扩展调参。fixture 只能用于 debug，不能替代真实 ResNet-50 formal input。

Phase 0

Real Trace

采集真实 ResNet-50 NVBit trace 和 scheduler metadata，建立 formal input。

Phase 1

Trace To Graph

Gate1-4: adapter、representative SM、canonical graph、tensorization。

Phase 2

Embedding

Gate5: RGCN contrastive training，导出 canonical 256D kernel embedding。

Phase 3

Selector

Gate6: silhouette-K、deterministic K-Means、representative anchors。

Phase 4

Correctness

Gate7: geometry、family、representative、metric、stability 五层定量验证。

实施顺序

先做
  • 修正 Gate1-5 formal path，使 fixture 只能 debug。
  • 实现 Gate0 真实 ResNet-50 NVBit trace acquisition。
  • 用真实 ResNet-50 trace 跑通 Gate1-5。
  • 实现 Gate6 selector 和 Gate7 correctness evaluation。
后做
  • Gate8 cluster / family 到 tuning vector proposal。
  • Gate9 sampled-vs-full simulator evaluation。
  • 只有 Gate9 通过后，才能声明 speedup / error claim。
Gate0-6 可以称为 GCL-Sampler 核心复现路径；Gate7 是可信度验证；Gate8-9 是我们的扩展，不应混入原始 GCL 复现 claim。
