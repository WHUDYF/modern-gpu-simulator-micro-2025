这次 RLCR 打通了什么

这轮实现的核心不是最终分类 kernel，而是把 Gate 1 到 Gate 5 的工程链路、artifact 边界、hash、validator 和 replay 契约固定下来。当前测试闭环使用的是 ResNet-like fixture；按照修正后的 spec，formal path 必须改为读取真实完整 ResNet-50 NVBit trace，才能把 Gate 5 导出的 256 维 kernel_embedding_table.json 作为后续 Gate 6 输入。

Gate 1

Trace Adapter

formal path 读取真实完整 ResNet-50 NVBit trace，验证 scheduler_metadata_source = real_nvbit_smid，生成 adapter bundle。

Gate 2

Representative SM

从 scheduler metadata 中构造 SM 签名，并用 scheduler_signature_medoid_sm 选择代表 SM。

Gate 3

Canonical Graph

把 selected-SM all-CTA trace records 转为 canonical graph bundle，保留 warp / CTA 层级。

Gate 4

Tensorization

把 graph 转为 feature width 64 的 tensor bundle，并记录 representation mode 与 pseudo-node mode。

Gate 5

RGCN Export

执行 augmentation、RGCN/readout、embedding export，停止在 kernel_embedding_table.json。

Replay

Integrity Check

校验 embedding table、readout hash、selector coverage、pipeline provenance 与 disk-backed replay。

闭环结构图

图中上半部分是数据流，下半部分是 RLCR 加固后的校验边界。也就是说，artifact 不只是被生成， 还要能证明自己来自正确的上游，并且在失败恢复时不会留下旧成功结果。

Review 具体加固了哪些问题

Graph Integrity

trace 到 graph 的输入契约更硬

  • 必须记录 selected SM、CTA 映射、trace source 和 manifest 字段。
  • trace_index 必须唯一、连续，不能跳号或重复。
  • warp partition 排序改为 numeric 排序，避免 10 个以上 CTA 时字典序错位。
Replay Integrity

embedding 不能脱离 provenance

  • embedding table 必须绑定 readout manifest hash。
  • selector replay 必须验证 coverage，不能只看文件存在。
  • disk-backed stage 必须写回 replay / selector artifacts。
Recovery

失败路径不能留下旧成功结果

  • training / export / selector / readout OOM 会写 resource-blocked artifact。
  • resource-blocked 时会清理旧 success artifact 和 stale hashes。
  • blocked replay hash 不允许继续伪装成可用成功结果。
Measured Loop

M1 / baseline diagnosis 修正

RLCR 补上了 Gate 4 timing weight 需要的明确计时指标： gpu__time_duration.sum 和 sm__cycles_elapsed.sum。 缺失或无效的 selected_metrics.json 现在会显式失败，避免后续使用静默错误的 timing 权重。

Runtime

CLI 与顺序稳定性

Gate 1 resolver 支持 python -m 方式运行；Phase B ordering 被稳定下来， 让同一份输入在 disk-backed pipeline 中生成可复现 artifact。

本轮固定下来的 Artifact 契约

这些 artifact 是后续 Gate 6 clustering / family classification 的上游边界。 后续工作应该消费这些文件，而不是绕过 Gate 1-5 直接读取中间变量。

resnet50_trace_adapter_bundle.json Gate 1 输出。证明输入 trace sources 可读，并且 scheduler metadata 来自真实 NVBit SM ID 采集路径。
representative_sm_trace_manifest.json Gate 2 输出。记录 selected SM、selection policy、CTA 覆盖范围和 trace hash。
canonical_graph_bundle.json Gate 3 输出。保存 selected-SM all-CTA trace 生成的 canonical graph，不被 augmentation 覆盖。
graph_tensor_bundle.json Gate 4 输出。保存 64 维 node features、edge_index、edge_type 和 warp / CTA partition metadata。
readout_manifest.json Gate 5 中间契约。记录 node -> warp -> CTA -> selected SM -> kernel readout 层级。
kernel_embedding_table.json Gate 5 最终输出。导出 256 维 canonical kernel embedding，作为后续 selector / clustering 输入。
selector_artifacts.json 本轮不会作为 Gate 5 正常输出，但 replay / repair stage 必须能验证 selector 覆盖与 provenance。
resource_blocked_artifact.json OOM 或资源失败时的显式失败结果，用来替代旧 success artifact，避免误判 pipeline 已成功。
