Gate 2: Representative-SM Manifest

Gate 2 消费 Gate 1 的 ResNet-50 trace adapter bundle，选择 representative SM，并生成现有 Phase B pipeline 可直接消费的 manifest。

输入 resnet50_trace_adapter_bundle.json，必须是 Gate 1 formal passed bundle。
选择算法 scheduler_signature_medoid_sm，使用等权 L2 距离和 deterministic tie-break。
正式输出 representative_sm_trace_manifest.json，作为 Gate 3 graph construction 入口。
禁止事项 不读原始 trace，不构图，不训练 GNN，不做 classification。

1. Gate 2 的职责

Gate 2 把 Gate 1 的通用 adapter bundle 转换成 Phase B 专用 representative-SM manifest。

Gate 1 Bundle

  • kernel invocation table
  • CTA scheduler records
  • per-warp trace records

Group by SM

  • cta_to_sm
  • scheduler_metadata_by_sm
  • before-scope counts

Select SM

  • raw signature
  • min-max normalization
  • equal-weight L2

Build Manifest

  • selected SM
  • included CTAs
  • inline policy report

Gate 3 Input

  • Phase B validator passes
  • per-warp records available
  • no raw trace dependency

2. 输入 Gate

Accept

Gate 2 只接受 scheduler_metadata_source = real_nvbit_smid 且 adapter_validation_report.status = passed 的 Gate 1 bundle。

Reject

simulator_replay、file_order_fallback、debug bundle、缺失 hash 或 hash 不可复现的输入都必须拒绝。

3. 字段映射

Gate 2 的核心工作是把 CTA 调度记录转换成 Phase B selection input。

Gate 1 cta_scheduler_records

  • kernel_invocation_id
  • cta_id
  • sm_id
  • warp_ids
  • trace_entry_count
  • first_seen_order
  • last_seen_order
->

Phase B scheduler_metadata_by_sm

  • cta_ids
  • warp_ids_by_cta
  • trace_entry_count_by_cta
  • cta_start_order
  • cta_end_order
  • cta_to_sm
included_cta_ids =
  scheduler_metadata_by_sm[str(selected_sm)].cta_ids

4. Representative SM Selection

Gate 2 使用 Phase B 已定义的 scheduler_signature_medoid_sm。

Signature

cta_count、warp_count、instruction_count_proxy、CTA start/end order、wave coverage、tail ratio。

Normalize

同一个 kernel invocation 内对所有 candidate SM 做 per-kernel min-max normalization。

Select

计算到 global normalized scheduler signature 的等权 L2 距离，最小者成为 selected SM。

禁止 random SM、first observed SM、max-instruction-only SM 或 LLM-generated selected SM 进入 formal manifest。

5. 输出 Artifacts

Manifest

representative_sm_trace_manifest.json 是后续 Phase B graph stage 的正式入口。

Evidence

selected_sm_policy_report.json 保存所有 candidate SM signature、距离和 selection hash。

Preview

scope_preview_report.json 审计 before/after scope 规模，不改变 formal manifest。

{
  "artifact_type": "gcl_phase_b_trace_manifest",
  "manifest_version": "gcl_phase_b_trace_manifest_v1",
  "collection_scope": "single_representative_sm_all_ctas",
  "kernel_invocations": [],
  "trace_manifest_hash": "..."
}

6. 通过标准

  • 输入 bundle 是 Gate 1 formal passed bundle。
  • 每个 formal invocation 都有 scheduler_metadata_by_sm。
  • 每个 formal invocation 都有 deterministic selected_sm_policy_report。
  • included_cta_ids 只来自 selected SM，并覆盖 selected SM 全部 CTA。
  • before-scope 和 after-scope 的 instruction / warp counts 与 trace entries 一致。
  • selection_hash、trace_hash、trace_manifest_hash 可复现。
  • 现有 Phase B validator 接受输出 manifest。
  • Gate 3 只需读取 manifest，不需要读取 Gate 1 bundle 或原始 trace。
Gate 2 通过后，真实 ResNet trace 已经具备进入 per-warp graph construction 的正式入口。
