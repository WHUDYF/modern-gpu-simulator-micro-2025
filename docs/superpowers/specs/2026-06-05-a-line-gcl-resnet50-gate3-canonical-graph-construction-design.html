Gate 3: Canonical Graph Construction

Gate 3 把 Gate 2 的 representative-SM manifest 转换成 GCL canonical graph bundle，并输出 audit-only graph size report。

输入 representative_sm_trace_manifest.json，必须通过 Phase B manifest validator。
核心输出 canonical_graph_bundle.json，作为 Gate 4 tensorization 的正式输入。
图结构 instruction / variable / pseudo nodes，control-flow 和 data-flow edges。
只 Audit graph size class 只记录规模，不自动截断 trace scope。

1. Gate 3 流程

Gate 3 只解决 selected-SM trace 到 canonical graph 的转换，不碰 tensor、训练和分类。

Gate 2 Manifest

  • selected SM
  • included CTAs
  • all trace entries

Trace Records

  • filter selected SM CTAs
  • group by CTA / warp
  • assign warp partitions

Per-Warp Graphs

  • instruction nodes
  • variable nodes
  • mem_ref pseudo nodes

Audit

  • node / edge counts
  • size class
  • no scope modification

Gate 4 Input

  • canonical graph bundle
  • warp partitions
  • replayable hashes

2. Selected-SM Trace Records

Gate 3 先把 manifest 里的完整 trace entries 收敛到 selected SM scope。

included_cta_ids = manifest invocation included_cta_ids
scoped_entries = all_trace_entries where cta_id in included_cta_ids
group scoped_entries by (cta_id, warp_id)
sort each warp entries by trace_index
assign warp_partition_id = "{cta_ordinal}:{warp_id}"
CTA ordinal 来自 selected SM 的 cta_start_order，因此 partition ID 可 replay。

3. Node 与 Edge

Graph 中的 node 和 edge 不是占位符，而是 selected-SM trace 中的执行实体和关系。

Instruction Node

每条动态 trace entry 变成一个 instruction node，记录 opcode、PC、CTA、warp、trace index 和 source entry hash。

Variable Node

source / destination operands 变成 variable nodes。寄存器在每个 warp partition 内稳定版本化。

Pseudo Node

第一版只生成 mem_ref pseudo node，用于表示 memory reference 中间语义。

control_flow

同一 warp 内动态 instruction 的前后控制依赖与执行顺序。control bits / predicate / active mask 作为 instruction node 属性保留。

data_source

变量或 memory reference 被 instruction 消费，例如 R8.v1.w0 -> FADD。

data_destination

instruction 产生变量新版本，例如 LDG -> R8.v1.w0。

Memory Opcode

LDG* / STG* 的地址 source operand 被识别为 address variable。

->

Memory Subgraph

address variable -> mem_ref pseudo -> memory instruction

HTML 中的 control lane / data lane 只是为了视觉拆分；正式 artifact 仍然是一个 canonical graph，里面同时包含 control-flow 和 data-flow typed edges。

4. Trace 到 Graph 示例

下面是一个 warp partition 内的简化 trace 如何变成图。实际 ResNet trace 会更长，但转换规则相同。

t0: MOV           dst=[R4]   src=[input:base]
t1: LDG.E.64.SYS dst=[R8]   src=[R4]
t2: FADD          dst=[R9]   src=[R8, input:bias]
t3: STG.E.64.SYS dst=[]     src=[R4, R9]

Instruction Nodes

i:t0(MOV)

i:t1(LDG)

i:t2(FADD)

i:t3(STG)

+

Control Flow

i:t0 -> i:t1

i:t1 -> i:t2

i:t2 -> i:t3

+

Data Flow

input:base -> i:t0 -> R4.v1.w0

R4.v1.w0 -> mem_ref:t1 -> i:t1 -> R8.v1.w0

R8.v1.w0 -> i:t2 -> R9.v1.w0

R4.v1.w0 -> mem_ref:t3 -> i:t3

这个例子展示了三件事：指令序列由 control-flow 保留，寄存器依赖由 variable node 和 data-flow 保留，memory reference 由 mem_ref pseudo node 显式化。

5. Warp Partition 约束

Allowed
  • control-flow edge 只连接同一 warp 内相邻 instruction nodes。
  • data_source / data_destination edge 留在同一 warp partition 内。
  • 每个 node / edge 属于且只属于一个 warp partition。
Rejected
  • 不同 warp 被串成一条 control-flow 主链。
  • edge 引用不存在的 node。
  • partition 引用不存在或重复归属的 node / edge。

6. Canonical Graph Bundle

Gate 3 的正式输出是 canonical graph bundle，每个 kernel invocation 对应一个 graph。

{
  "artifact_type": "gcl_resnet50_canonical_graph_bundle",
  "artifact_version": "gate3_canonical_graph_bundle_v1",
  "source_trace_manifest_hash": "...",
  "graphs": [],
  "canonical_graph_bundle_hash": "..."
}

每个 graph 包含 nodes、edges、warp_partitions、graph_summary 和可复现的 graph_hash。

7. Graph Size Audit

Audit 记录规模，但不改变 graph，也不因为 size class 自动阻断 Gate 4。

Counts

instruction count、warp count、node count、edge count、各类 node / edge count。

Size Class

small、medium、large、oversized 只表示 audit class。

No Mutation

trace_scope_modified_after_audit = false，canonical graph hash 必须保持不变。

如果后续资源真的不足，只能由 Gate 4 或训练阶段输出 resource-blocked artifact；Gate 3 不做 compression 或 truncation。

8. 通过标准

  • 输入 manifest 通过现有 Phase B manifest validator。
  • 每个 selected SM invocation 都能生成 selected-SM trace records。
  • 每个 warp partition 非空，并至少包含一个 instruction node。
  • control-flow 和 data-flow edge 不跨 warp partition。
  • 每个 graph node / edge 属于且只属于一个 warp partition。
  • register version 由 graph builder 稳定生成。
  • memory opcode 的 mem_ref pseudo node 与 address source edge 一致。
  • graph_hash、bundle hash 和 audit hash 都可复现。
  • Gate 4 只需要读取 canonical_graph_bundle.json。
